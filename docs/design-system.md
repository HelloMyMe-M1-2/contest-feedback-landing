# 랜딩페이지 디자인 기준 초안

> 2026-11-17 · 팀 검토용 임시 기준입니다. 디자인 담당자가 결정한 최종 브랜드 규칙이 아닙니다. 새로운 합의나 명시적인 요청이 생기면 이 문서와 코드를 함께 바꿉니다.

## 이 화면의 목적

공모전 참가자가 **무엇을 확인할 수 있는 서비스인지**와 **가상의 피드백 예시**를 이해하도록 돕습니다. 실제 분석·결제는 제공하지 않으며 효과도 검증되지 않았습니다. 이런 상태를 화면에서 숨기지 않습니다.

분위기는 `차분함 · 명료함 · 약간의 따뜻함`을 기준으로 합니다. 기획안의 문장, 확인할 부분, 이유, 점검 기준을 읽기 쉽게 보여주는 것이 화면의 중심입니다. 장식이나 움직임보다 내용과 사용 흐름이 먼저 보이도록 합니다.

## 현재 화면에 적용한 값

실제 구현의 기준은 `src/styles.css`입니다. 아래는 현재 랜딩 화면의 주요 값으로, 모든 요소가 이 값만 사용한다는 뜻은 아닙니다.

| 항목 | 현재 기준 | 이유 |
| --- | --- | --- |
| 바탕색 | `#f8f8f3` | 종이를 연상시키는 밝은 바탕 |
| 기본 글자 | `#20302d` | 긴 글과 제목을 편하게 읽을 수 있도록 짙은 색 사용 |
| 보조·설명 글자 | `#52665b` | 옅은 회색보다 읽기 쉽게 조정 |
| 강조·주요 버튼 | `#335b4d`, 흰색 글자 | 예시 보기와 구매 버튼의 역할을 일관되게 표현 |
| 강조 영역 배경 | `#e8efe6` | 보조적인 구분. 가격이나 이용 가능 상태를 색만으로 전달하지 않음 |
| 버튼 높이 | 예시 보기·구매 버튼 최소 52px, 예시 선택 버튼 최소 44px | 손가락으로 누르기 편한 크기 |
| 버튼 모서리 | 주요 버튼 8px | 반복되는 조작의 모양을 일관되게 유지 |
| 글자 | 기기의 한국어 시스템 글꼴, 본문 주로 14–16px | 추가 글꼴 다운로드 없이 읽기 쉬운 화면 제공 |
| 화면 너비 | 820px 이하에서 첫 화면을 한 단으로 배치 | 768px에서 두 단의 문서 영역이 지나치게 좁아지는 문제 해결 |
| 여백 | 주요 간격은 4px의 배수를 우선. 기존의 예외 값도 남아 있음 | 관계가 가까운 요소는 모으고, 별도 섹션은 분리 |
| 움직임 | 기본적인 색 변화와 화면 내 이동만 사용. 움직임 감소 설정을 존중 | 사용자의 선택과 읽기를 방해하지 않도록 함 |

이 값은 `:root`의 `--ink`, `--text-secondary`, `--accent`, `--surface-page` 등과 각 요소의 CSS로 정의합니다. 현재는 일부만 공통 변수로 묶여 있으므로 모든 스타일의 완전한 자동 일관성을 보장하지 않습니다. 새 화면을 만들 때 이미 있는 값을 먼저 사용하고 반복되는 값은 필요할 때만 공통화합니다.

## 화면과 문구를 바꿀 때

1. 예시가 **가상의 예시**이며 실제 심사 의견이나 분석 결과가 아니라는 설명을 유지합니다.
2. 가격·제공 범위가 미정이고 결제와 서비스가 준비되지 않았다는 사실을 흐리지 않습니다. 실제 구매가 완료된 것처럼 보이게 하지 않습니다.
3. 버튼과 예시는 키보드로 조작할 수 있어야 하고, 포커스가 보이도록 합니다.
4. 디자인을 바꾸면 모바일과 데스크톱에서 글자 겹침·가로 넘침·터치 영역·대비를 확인합니다. `prefers-reduced-motion`도 유지합니다.
5. 예시나 버튼 위치·크기, 문구를 바꾸면 이벤트의 의미와 노출 조건이 그대로인지 [측정 변경 안내](measurement-change-guide.md)를 확인합니다. 같은 이벤트 이름이어도 화면이 달라지면 전환율이 같게 유지된다는 뜻은 아닙니다.
6. 새 디자인이 확정되면 색상, 크기, 간격과 이유를 이 문서에 갱신합니다. 팀의 결정은 이 임시 초안보다 우선합니다.

이번 개선에서 확인한 문제와 도구 선택 이유는 [디자인 검토 기록](design-review-2026-11-17.md)에 정리했습니다.
