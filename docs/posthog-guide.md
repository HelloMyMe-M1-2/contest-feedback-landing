# PostHog 처음 사용하기

## 지금 어디까지 왔나요?

**PostHog 프로젝트에 개발자 로컬 테스트 이벤트가 도착하는 것을 확인했습니다.** 기본 로컬 실습은 이벤트를 브라우저 메모리에 최대 100개 저장하며 새로고침하면 사라집니다. 별도 설정을 켜면 로컬 테스트 이벤트를 PostHog로 보낼 수 있습니다. 실습장은 PostHog 화면을 재현한 것이 아니라, 이벤트의 원리를 배우는 도구입니다. 실제 방문자 데이터 수집은 아직 연결되지 않았습니다.

## PostHog가 하는 일

PostHog는 웹사이트나 앱에서 발생한 행동을 모아 분석하는 도구입니다. 사이트에 측정 코드를 연결한 다음 행동마다 이벤트를 보내면, PostHog에서 이벤트 수나 단계별 전환을 살펴볼 수 있습니다. 숫자를 해석하려면 어떤 행동을 언제 이벤트로 정했는지 먼저 알아야 합니다.

| 개념 | 뜻 | 우리 예시 |
| --- | --- | --- |
| 이벤트 | 일어난 행동 하나 | `purchase_clicked`: 구매 버튼을 누름 |
| 이벤트 속성 | 그 행동을 설명하는 값 | `price_status: not_set`: 가격을 아직 표시하지 않음 |
| 유입 정보 | 어느 게시글에서 왔는지 설명하는 값 | `post_id: post_001` |
| 방문자 | 식별자를 바탕으로 추정한 사용자 | 여러 기기·브라우저는 같은 사람으로 자동 확정할 수 없음 |
| 세션 | 관련된 행동을 묶어 보는 방문 단위 | 실제 사람 수와 다르며 기준을 확인해야 함 |
| 퍼널 | 정해진 단계를 얼마나 진행했는지 보는 분석 | 방문 → 예시 노출 → 구매 조건 노출 → 클릭 |
| 대시보드 | 필요한 그래프를 한 곳에 모은 화면 | 게시글별 유입과 구매 클릭을 나란히 확인 |

예를 들어 어떤 한 페이지 방문에서 구매 버튼을 세 번 누르면 **클릭 이벤트는 3건**입니다. 행동한 **세션은 1개**일 수 있습니다. 한 사람이 휴대폰과 PC로 접속하면 서로 다른 방문자로 추정될 수도 있습니다.

## 직접 실습하기

1. 프로젝트 폴더에서 `npm run dev`를 실행합니다.
2. 아래 주소를 브라우저에 입력합니다.

```text
http://127.0.0.1:5173/?analytics_lab=1&utm_source=linkareer&utm_medium=post&utm_campaign=pilot&utm_content=post_001
```

터미널에 표시된 주소의 포트가 `5173`이 아니라면, 위 주소에서도 같은 포트 번호로 바꿉니다.

3. 페이지 아래의 **이벤트 실습장**을 봅니다. `landing_viewed`는 페이지를 열었다는 이벤트입니다.
4. 예시가 충분히 보이도록 기다린 뒤 다른 예시 버튼을 누릅니다. `example_exposed`는 보인 것, `example_selected`는 누른 것입니다.
5. 구매 버튼을 누릅니다. `purchase_clicked`와 준비 중 안내가 나타난 뒤의 `availability_notice_viewed`를 비교합니다. 구매 조건 영역을 2초 이상 보면 `purchase_offer_viewed`도 기록될 수 있습니다.
6. 각 기록의 `campaign`에서 `post_id: post_001`을 확인합니다. 이 값으로 어느 게시글 링크인지 구분하도록 설계했습니다.
7. 새로고침하면 실습 기록이 사라집니다. `실습 기록 비우기`는 현재 목록만 비우며, 이미 발생한 페이지 방문·노출 이벤트를 다시 발생시키지 않습니다.
8. 실습장에 보이는 경과 시간과 화면 표시 시간을 비교합니다. 다른 탭에 잠시 갔다가 돌아오면 경과 시간은 늘지만 그동안 화면 표시 시간은 늘지 않습니다. 15초마다와 숨김 시 누적값을 실습 이벤트로 기록합니다. PostHog 테스트 모드를 별도로 켠 경우에만 외부로 전송합니다.

실습장은 개발 서버의 localhost 또는 127.0.0.1과 `analytics_lab=1` 조건에서만 열립니다. 일반 주소와 운영 빌드에서는 보이지 않습니다. 실제 이메일이나 개인정보가 들어간 값을 URL에 넣지 마세요.

## 체류시간은 무엇을 뜻하나요?

- **페이지 경과 시간:** 한 페이지를 연 후 흘러간 시간입니다. 다른 탭을 보는 시간도 포함될 수 있습니다.
- **화면 표시 시간:** 브라우저가 페이지를 표시 중이라고 알려 준 시간만 누적합니다. 다른 탭이나 앱으로 전환된 시간은 제외하지만, 페이지를 켜놓고 자리를 비운 경우도 포함될 수 있습니다. 실제로 읽었는지는 알 수 없습니다.
- **PostHog 세션 시간:** PostHog가 정한 하나의 세션에 속한 활동을 기준으로 산정하는 시간입니다. 페이지 한 번의 체류시간이나 화면 표시 시간과 같은 지표가 아닙니다.

예를 들어 60초 동안 페이지를 열고 그중 40초는 다른 탭을 보면 경과 시간은 약 60초, 화면 표시 시간은 약 20초입니다. 실제 수집 시에는 탭 상태 변화, 주기적 중간 기록, 전송 실패와 강제 종료 등을 검토해야 합니다. 기록이 없다는 것은 0초와 다르며 화면 표시 시간이 읽기를 증명하지 않습니다. 브라우저 절전 등으로 시간 계산에 오차가 생길 수도 있습니다.

PostHog는 연결과 설정에 따라 페이지 체류시간을 분석할 수 있습니다. 화면 표시 시간은 같은 값이라고 가정하지 말고 별도 구현과 검증이 필요합니다. 현재는 로컬 테스트 모드에서만 누적 시간을 PostHog에 전송할 수 있습니다.

## PostHog에 테스트 이벤트 보내기

이 단계는 **개발자 자신의 로컬 테스트만**을 위한 것입니다. 실제 참가자에게 사이트를 공개하거나 개인정보를 입력해 시험하지 않습니다. PostHog에는 테스트 이벤트와 가상의 게시글 정보가 전송됩니다. 초기 테스트 이벤트에는 IP와 위치 추정 정보가 저장됐습니다. 이후 프로젝트의 `Discard client IP data`를 켜고 테스트 코드에 GeoIP 비활성화 요청을 추가했으며, 새 테스트 이벤트 한 건에서 IP와 위치 추정 항목이 보이지 않는 것을 확인했습니다. 기존 기록은 자동 삭제되지 않습니다. 실험 참가자 수집을 시작하기 전 안내·동의, IP·URL·식별자, 국외 처리와 보관·삭제를 따로 검토해야 합니다.

1. [PostHog](https://posthog.com/)에서 계정과 프로젝트를 준비합니다. 무료 플랜의 프로젝트를 운영에도 함께 쓸 계획이라면 `contest-feedback-landing`처럼 프로젝트의 목적을 나타내는 이름을 권장합니다. 가입 지역에 따라 데이터 처리 지역이 달라지므로 생성 시 확인하세요.
2. 프로젝트 설정에서 **Project token**과 **Host**를 확인합니다. `phc_`로 시작하는 프로젝트 토큰은 브라우저용 수집 토큰입니다. 권한이 다른 **Personal API key는 사용하거나 공유하지 않습니다.**
3. 이 저장소 폴더의 `.env.example`을 복사해 `.env.local` 파일을 만들고 자신의 프로젝트 값을 입력합니다. `.env.local`은 Git에 포함하지 않습니다. 개인 API 키를 입력하거나 채팅에 토큰을 보내지 마세요.

```text
VITE_POSTHOG_TEST_TOKEN=phc_여기에_프로젝트_토큰
VITE_POSTHOG_TEST_HOST=https://us.i.posthog.com
```

위 호스트는 미국 리전 예시입니다. EU 리전이라면 `https://eu.i.posthog.com`을 사용합니다. 프로젝트 설정에서 확인한 지역에 맞는 공식 수집 호스트만 허용하며 마지막 `/`는 넣지 않습니다. 토큰 자리에는 설명을 제외한 실제 프로젝트 토큰만 넣습니다.

4. 파일을 저장한 뒤 개발 서버를 새로 시작합니다. 실행 중인 서버가 있다면 `Ctrl+C`로 종료하고 `npm run dev`를 실행합니다.
5. 다음 주소를 엽니다. **이 주소를 연 경우 이벤트가 외부 PostHog 프로젝트로 전송됩니다.**

```text
http://127.0.0.1:5173/?analytics_lab=1&posthog_test=1&utm_content=post_001
```

여기서도 터미널에 표시된 로컬 주소의 포트를 사용합니다.

6. 실습장에 **PostHog 테스트 전송이 켜져 있습니다**가 보이는지 확인하고 예시와 구매 버튼을 눌러 봅니다. PostHog의 이벤트 목록 또는 활동 화면에서 `landing_viewed`, `example_selected`, `purchase_clicked` 등을 찾습니다. 이벤트를 열면 `test_environment: local`과 고정된 `post_id: test_post_001`을 볼 수 있습니다. 화면 이름은 PostHog UI 변경에 따라 달라질 수 있습니다.
7. 같은 구매 버튼을 세 번 누르면 로컬에는 `purchase_clicked`가 세 건 표시됩니다. PostHog에서도 세 건이 도착하는지 확인합니다. 표시 지연이나 전송 차단이 있으면 PostHog 화면, 브라우저 네트워크 오류와 로컬 토큰·호스트를 확인합니다.

별도 설정을 하지 않거나 일반 주소를 열면 전송하지 않습니다. 운영 빌드와 외부 주소에서는 위 쿼리나 토큰이 있더라도 테스트 전송이 켜지지 않습니다. 테스트에서는 PostHog의 자동 클릭·페이지 수집, 세션 녹화, 기능 플래그 요청을 끄고 테스트 이벤트만 전송하도록 설정했습니다. URL과 referrer 등은 전송 이벤트에서 제거하며, 테스트 유입 속성은 정해진 가상 값으로 사용합니다. `post_001`과 `post_002`는 각각 `test_post_001`과 `test_post_002`로 바뀌고, 나머지는 `test_unknown`입니다. 그래도 네트워크 요청 자체의 IP 등까지 없어지는 것은 아닙니다.

테스트의 PostHog 식별은 브라우저 메모리에서만 유지하도록 설정해 새로고침하면 달라질 수 있습니다. 로컬 실습장의 `실습 기록 비우기`는 화면만 지우며 이미 PostHog로 전송된 이벤트는 삭제하지 않습니다. 테스트 모드는 체류시간과 스크롤 이벤트를 전송하지만 **실제 실험 참가자는 기록하지 않습니다.**

무료 플랜의 프로젝트 하나를 테스트와 운영에 함께 사용하는 방식을 우선합니다. 현재 로컬 테스트 이벤트에는 `test_environment: local`이 붙습니다. 운영 전에는 운영 이벤트에도 같은 구분 속성을 명시하고, 분석에서 운영 값만 포함하는 필터를 모든 단계에 적용·검증해야 합니다. 필터를 빠뜨리거나 구분 속성이 없는 이벤트가 생기면 테스트가 결과에 섞이거나 실제 방문이 누락될 수 있습니다. 테스트 이벤트는 운영 기간을 정해 별도로 살펴볼 수도 있으나, 이는 필터를 대체하지 않습니다. 테스트 데이터 삭제 방법은 익명 이벤트의 처리 방식과 권한을 포함해 실제 실험 전에 확인합니다. 이벤트 정의를 삭제하는 것은 수집된 이벤트 데이터를 삭제하는 것과 다릅니다.

### PostHog에서 테스트 이벤트 보기

1. PostHog 왼쪽 메뉴에서 **Activity**를 선택합니다.
2. **Property filters**를 누르고 `test_environment`를 검색해 이벤트 속성을 선택합니다.
3. `equals`의 값으로 `local`을 선택하면 로컬 테스트 이벤트를 볼 수 있습니다. 항목을 펼치면 이벤트의 속성도 확인할 수 있습니다.
4. 이 필터는 현재 보고 있는 목록의 조건입니다. 모든 대시보드와 퍼널에 자동 적용된다고 가정하지 않습니다. 운영 이벤트는 아직 구현되지 않았으며, 실제 실험 전 운영 구분값 필터를 별도로 적용하고 검증합니다.

### IP와 위치 정보에 관해

PostHog 프로젝트의 **Settings → Project → Privacy → Discard client IP data**를 켰습니다. 이 설정은 새로운 이벤트에 원본 클라이언트 IP를 저장하지 않도록 합니다. PostHog가 IP를 수신하지 않는다는 뜻은 아니고, 저장 전 변환에서 위치 추정 등에 사용할 수 있습니다. 테스트 코드의 `$geoip_disable`은 해당 테스트 이벤트에 위치 추정을 하지 않도록 요청합니다. 새 테스트 한 건의 확인 결과를 전체 수집 경로의 보장으로 해석하지 말고 운영 연결 시 다시 검증합니다.

## 실제 프로젝트에 연결한다면

다음은 실제 실험 수집까지의 절차입니다. 개발자 로컬 테스트 이벤트 수신만 확인했으며 나머지는 아직 완료되지 않았습니다.

1. 팀이 관리할 PostHog 계정·프로젝트를 준비하고 테스트와 운영 데이터를 분리합니다.
2. 수집할 이벤트와 실제 필요한 개인정보 고지·동의, 보관·삭제, 국외 처리 조건을 확인합니다.
3. SDK의 자동 수집 범위와 세션 녹화 등 기본 설정을 확인하고 필요한 이벤트만 보내도록 구성합니다. 기본 설정이 프로젝트의 개인정보 방침과 자동으로 일치한다고 가정하지 않습니다.
4. 개발 환경의 가상 이벤트로 실제 PostHog에 도착하는 이벤트와 속성을 확인하고 테스트 데이터를 운영 분석에서 분리합니다.
5. 데이터가 검증되면 트렌드에서 게시글별 유입과 이벤트 수를 보고, 퍼널에서 단계 순서와 세션 기준을 명시합니다. 게시글 조회 수는 커뮤니티에서 별도로 기록합니다.

PostHog의 브라우저용 **프로젝트 토큰**은 이벤트 수집을 위해 노출될 수 있는 값입니다. 반면 **개인 API 키**는 권한을 부여할 수 있으므로 코드나 채팅에 공유하지 않습니다. 프로젝트 토큰을 쓴다고 수집 데이터가 자동으로 익명화되는 것도 아닙니다. IP를 버리는 서버 설정은 데이터가 전송된 뒤의 저장 처리이므로, 전송 자체와 URL 등 다른 수집 항목도 따로 확인해야 합니다.
