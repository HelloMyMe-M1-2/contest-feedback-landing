# PostHog 처음 사용하기

## 지금 어디까지 왔나요?

**PostHog는 아직 연결되지 않았습니다.** 이 프로젝트는 개발 중에만 여는 로컬 실습장을 제공하며 기록을 브라우저 메모리에 최대 100개 저장합니다. 새로고침하면 사라지고 서버나 PostHog로 전송되지 않습니다. 이 실습은 PostHog 화면을 재현한 것이 아니라, 이벤트의 원리를 배우는 도구입니다.

## PostHog가 하는 일

PostHog는 웹사이트나 앱에서 발생한 행동을 모아 분석하는 도구입니다. 사이트에 측정 코드를 연결한 다음 행동마다 이벤트를 보내면, PostHog에서 이벤트 수나 단계별 전환을 살펴볼 수 있습니다. 숫자를 해석하려면 어떤 행동을 언제 이벤트로 정했는지 먼저 알아야 합니다.

| 개념 | 뜻 | 우리 예시 |
| --- | --- | --- |
| 이벤트 | 일어난 행동 하나 | `purchase_clicked`: 구매 버튼을 누름 |
| 이벤트 속성 | 그 행동을 설명하는 값 | `price_status: not_set`: 가격을 아직 표시하지 않음 |
| 유입 정보 | 어느 게시글에서 왔는지 설명하는 값 | `post_id: post_001` |
| 방문자 | 식별자를 바탕으로 추정한 사용자 | 여러 기기·브라우저는 같은 사람으로 자동 확정할 수 없음 |
| 세션 | 관련된 행동을 묶어 보는 방문 단위 | 실제 사람 수와 다르며 기준을 확인해야 함 |
| 퍼널 | 정해진 단계를 얼마나 진행했는지 보는 분석 | 방문 → 예시 노출 → 구매 조건 노출 → 클릭 |
| 대시보드 | 필요한 그래프를 한 곳에 모은 화면 | 게시글별 유입과 구매 클릭을 나란히 확인 |

예를 들어 어떤 한 페이지 방문에서 구매 버튼을 세 번 누르면 **클릭 이벤트는 3건**입니다. 행동한 **세션은 1개**일 수 있습니다. 한 사람이 휴대폰과 PC로 접속하면 서로 다른 방문자로 추정될 수도 있습니다.

## 직접 실습하기

1. 프로젝트 폴더에서 `npm run dev`를 실행합니다.
2. 아래 주소를 브라우저에 입력합니다.

```text
http://127.0.0.1:5173/?analytics_lab=1&utm_source=linkareer&utm_medium=post&utm_campaign=pilot&utm_content=post_001
```

3. 페이지 아래의 **이벤트 실습장**을 봅니다. `landing_viewed`는 페이지를 열었다는 이벤트입니다.
4. 예시가 충분히 보이도록 기다린 뒤 다른 예시 버튼을 누릅니다. `example_exposed`는 보인 것, `example_selected`는 누른 것입니다.
5. 구매 버튼을 누릅니다. `purchase_clicked`와 준비 중 안내가 나타난 뒤의 `availability_notice_viewed`를 비교합니다. 구매 조건 영역을 2초 이상 보면 `purchase_offer_viewed`도 기록될 수 있습니다.
6. 각 기록의 `campaign`에서 `post_id: post_001`을 확인합니다. 이 값으로 어느 게시글 링크인지 구분하도록 설계했습니다.
7. 새로고침하면 실습 기록이 사라집니다. `실습 기록 비우기`는 현재 목록만 비우며, 이미 발생한 페이지 방문·노출 이벤트를 다시 발생시키지 않습니다.
8. 실습장에 보이는 경과 시간과 화면 표시 시간을 비교합니다. 다른 탭에 잠시 갔다가 돌아오면 경과 시간은 늘지만 그동안 화면 표시 시간은 늘지 않습니다. 표시용이며 기록·전송하지 않습니다.

실습장은 개발 서버의 localhost 또는 127.0.0.1과 `analytics_lab=1` 조건에서만 열립니다. 일반 주소와 운영 빌드에서는 보이지 않습니다. 실제 이메일이나 개인정보가 들어간 값을 URL에 넣지 마세요.

## 체류시간은 무엇을 뜻하나요?

- **페이지 경과 시간:** 한 페이지를 연 후 흘러간 시간입니다. 다른 탭을 보는 시간도 포함될 수 있습니다.
- **화면 표시 시간:** 브라우저가 페이지를 표시 중이라고 알려 준 시간만 누적합니다. 다른 탭이나 앱으로 전환된 시간은 제외하지만, 페이지를 켜놓고 자리를 비운 경우도 포함될 수 있습니다. 실제로 읽었는지는 알 수 없습니다.
- **PostHog 세션 시간:** PostHog가 정한 하나의 세션에 속한 활동을 기준으로 산정하는 시간입니다. 페이지 한 번의 체류시간이나 화면 표시 시간과 같은 지표가 아닙니다.

예를 들어 60초 동안 페이지를 열고 그중 40초는 다른 탭을 보면 경과 시간은 약 60초, 화면 표시 시간은 약 20초입니다. 실제 수집 시에는 탭 상태 변화, 주기적 중간 기록, 전송 실패와 강제 종료 등을 검토해야 합니다. 기록이 없다는 것은 0초와 다르며 화면 표시 시간이 읽기를 증명하지 않습니다. 브라우저 절전 등으로 시간 계산에 오차가 생길 수도 있습니다.

PostHog는 연결과 설정에 따라 페이지 체류시간을 분석할 수 있습니다. 화면 표시 시간은 같은 값이라고 가정하지 말고 별도 구현과 검증이 필요합니다. 지금은 어느 시간도 PostHog로 전송되지 않습니다.

## 실제 프로젝트에 연결한다면

다음 절차는 **향후 작업 계획**이며 현재 완료되지 않았습니다.

1. 팀이 관리할 PostHog 계정·프로젝트를 준비하고 테스트와 운영 데이터를 분리합니다.
2. 수집할 이벤트와 실제 필요한 개인정보 고지·동의, 보관·삭제, 국외 처리 조건을 확인합니다.
3. SDK의 자동 수집 범위와 세션 녹화 등 기본 설정을 확인하고 필요한 이벤트만 보내도록 구성합니다. 기본 설정이 프로젝트의 개인정보 방침과 자동으로 일치한다고 가정하지 않습니다.
4. 개발 환경의 가상 이벤트로 실제 PostHog에 도착하는 이벤트와 속성을 확인하고 테스트 데이터를 운영 분석에서 분리합니다.
5. 데이터가 검증되면 트렌드에서 게시글별 유입과 이벤트 수를 보고, 퍼널에서 단계 순서와 세션 기준을 명시합니다. 게시글 조회 수는 커뮤니티에서 별도로 기록합니다.

PostHog의 브라우저용 **프로젝트 토큰**은 이벤트 수집을 위해 노출될 수 있는 값입니다. 반면 **개인 API 키**는 권한을 부여할 수 있으므로 코드나 채팅에 공유하지 않습니다. 프로젝트 토큰을 쓴다고 수집 데이터가 자동으로 익명화되는 것도 아닙니다. IP를 버리는 서버 설정은 데이터가 전송된 뒤의 저장 처리이므로, 전송 자체와 URL 등 다른 수집 항목도 따로 확인해야 합니다.
