# 이벤트 명세

## 지금 어디까지 동작하나요?

실제 분석 서비스에는 **연결되지 않았습니다.** 일반 화면의 이벤트 전송은 꺼져 있습니다. 로컬 개발 서버에서 `analytics_lab=1`을 붙여 열면 이벤트를 브라우저 메모리에만 기록해 살펴볼 수 있고, 새로고침하면 사라집니다. 실습장의 수치는 최대 100건이며 실제 방문자·세션 통계가 아닙니다.

실습장에는 페이지를 연 뒤 경과한 시간과 화면이 표시된 시간도 초 단위로 표시합니다. 탭이 숨겨져 있는 시간은 후자에 더하지 않습니다. 표시만 하며 이벤트로 저장하거나 전송하지 않습니다. 새로고침하면 다시 시작합니다.

| 이름 | 의미 | 현재 로컬 실습 |
| --- | --- | --- |
| `landing_viewed` | 페이지 방문 | 기록됨. Strict Mode의 개발용 재실행은 한 번으로 처리 |
| `example_exposed` | 예시 내용 노출 | 요소의 50% 이상이 화면에 보이고 탭이 표시 상태로 2초 유지되면 기록. 각 예시는 페이지 수명 중 1회 |
| `example_selected` | 사용자가 예시 버튼 선택 | 누를 때마다 기록 |
| `purchase_offer_viewed` | 구매 조건 영역 노출 | 50% 이상·2초 유지 시 페이지 수명 중 1회. 가격은 미정 |
| `purchase_clicked` | 구매 버튼 클릭 | 누를 때마다 기록. 결제 아님 |
| `availability_notice_viewed` | 준비 중 안내가 화면에 표시됨 | 표시 후 기록. 이미 열린 안내를 반복 클릭해도 새 표시로 세지 않음 |
| `registration_started` / `registration_completed` | 등록 시작 / 저장 성공 | 형식만 정의. 이메일 수집 보류 |
| `scroll_depth_reached` | 스크롤 구간 도달 | 형식만 정의 |
| `visibility_checkpoint` | 화면 표시 시간 구간 | 형식만 정의 |
| `general_click` | 일반 클릭 | 형식만 정의 |

이벤트에는 이름, 해당 행동의 속성, URL에서 읽은 유입 정보, 시각과 스키마 버전이 들어갑니다. `utm_content`는 게시글 ID로 사용합니다. 개발용 URL의 형식 검사만으로 개인정보를 완전히 차단할 수 없으므로, 실제 연결 전 팀이 발급한 값만 허용하는 방식을 정해야 합니다. 임의의 이메일·원고·개인정보는 URL에 넣지 않습니다.

## 앞으로 실제 연결할 때

- 이벤트 횟수와 행동한 세션 수를 분리한다. 같은 사람이 여러 기기에서 방문한 경우 동일인으로 확정할 수 없다.
- 로컬 노출 감지는 페이지 수명 기준이다. 실제 실험의 세션 기준, 화면 크기, 재노출, 탭 전환, 느린 브라우저와 누락을 별도로 검증한다.
- 구매 조건 노출 후 같은 세션에서 클릭한 비율을 별도로 보고, 가격과 제공 범위 버전을 함께 둔다. 실제 결제와 구분한다.
- 화면이 표시된 시간은 탭을 연 전체 시간과 구분한다. 강제 종료·통신 실패 등으로 누락될 수 있고 실제 읽기를 증명하지 못한다.
- 이메일 수집을 시작하게 될 경우 저장 성공 응답을 받은 때만 완료로 기록하고 저장소와 분석 수치를 대조한다.
- 운영 데이터를 연결하기 전 SDK의 자동 수집, 식별자, IP·URL, 세션 녹화, 쿠키, 동의, 보관·삭제, 국외 처리와 테스트 데이터 분리를 검토한다. 이메일·원고·입력값을 보내지 않는다.
- 현재 로컬 형식에는 이벤트 ID·세션 ID·기기 유형·환경과 가격 버전이 없다. 실제 퍼널 측정 전 속성과 전송 중복·오류 처리, 분석 설정을 구현·검증해야 한다.
