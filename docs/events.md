# PLAN:CHECK 측정 기준

이 문서는 **현재 원본 화면 기준**입니다. 화면의 색·문구·배치를 바꾸더라도 행동의 의미가 같으면 이벤트 이름과 기준을 유지합니다. 의미가 달라질 때는 기존 수치에 섞지 말고 아래 기준과 버전을 함께 수정합니다.

> 현재 이벤트는 개발자의 **로컬 실습·PostHog 테스트 전용**입니다. 실제 참가자 수집은 연결되지 않았고 대시보드도 아직 생성하지 않았습니다. 원본 화면에 구매 버튼은 없습니다. 이메일 저장용 시트는 로컬 가상 신청으로만 확인했으며 실제 사이트와는 연결되지 않았습니다.

## 기록할 행동

| 이벤트 | 발생 기준 | 주요 속성 | 중복 해석 |
| --- | --- | --- | --- |
| `landing_viewed` | 랜딩 화면을 열었을 때 | 공통 속성 | 페이지를 새로 열거나 새로고침할 때마다 1건 |
| `sample_report_viewed` | 샘플 리포트 뷰어 상단이 화면에 50% 이상, 탭 표시 상태로 연속 2초 보였을 때 | `sample_version` | 한 페이지에서 1회. 제목·뷰어가 보였다는 뜻이며 실제 내용을 읽었다는 뜻은 아님 |
| `sample_interacted` | 샘플 펼치기·확대·목차 선택 | `action`, `section_id` | 행동할 때마다 기록. 잠긴 목차를 선택하면 자동 펼치기와 목차 선택이 각각 기록될 수 있음 |
| `cta_clicked` | 샘플 또는 사전 신청 영역으로 이동하는 주요 버튼 클릭 | `target`, `location` | 클릭할 때마다 기록. 신청 완료가 아님 |
| `registration_started` | 이메일 입력란에 처음 포커스 | `form_version` | 한 페이지에서 1회. 이메일이나 입력 내용은 수집하지 않음 |
| `registration_completed` | 신청 저장 API가 성공 응답을 돌려준 경우 | `form_version`, `result` | 응답당 1건. `new`는 성공 응답에 붙이는 값이며 현재 중복 신청 여부·고유 인원을 보장하지 않음. 로컬 테스트에서 시트 저장과 PostHog 도착을 확인했으며 운영 환경은 미검증 |
| `scroll_depth_reached` | 콘텐츠 전체 높이 대비 화면 하단이 25·50·75·100%에 도달 | `depth` | 페이지당 각 구간 1회. 처음부터 여러 구간이 보일 수도 있음 |
| `visibility_checkpoint` | 화면 표시 중 약 15초마다, 숨김·페이지 이탈 시 | `visible_ms`, `elapsed_ms`, `click_count`, `sequence`, `trigger` | 값은 페이지별 누적값. 합산하지 말고 페이지별 **최댓값** 사용 |

공통 속성은 `page_view_id`, `device_category`, `event_schema_version`, `post_id`, `utm_source`, `utm_medium`, `utm_campaign`입니다. `page_view_id`는 페이지를 열 때 새로 발급하며 사람이나 PostHog 세션과 다릅니다. 기기 분류는 대략적이며 태블릿 등은 `other` 또는 `unknown`일 수 있습니다.

샘플 조작의 `action`은 `expand`(펼침), `zoom`(확대 창 열기), `section`(목차 선택)입니다. 목차 선택에는 의미가 고정된 `section_id`를 씁니다: `overview`, `criteria`, `strengths`, `basic`, `weaknesses`, `questions`, `deep`. 다른 조작은 `none`입니다. 제목이나 순서가 바뀌어도 같은 내용을 가리킨다면 ID를 유지합니다. 펼치기는 현재 닫힌 샘플을 처음 펼칠 때만 기록하고 이미 펼쳐진 상태에서의 클릭은 기록하지 않습니다.

`cta_clicked`의 `target`은 `sample` 또는 `signup`이며, `location`은 `header`, `drawer`, `hero`, `how`, `toc`, `after-sample`, `mbar` 중 하나입니다. 텍스트를 그대로 전송하지 않습니다. 목차나 CTA를 추가할 때는 분석에 쓸 고정 ID를 등록합니다.

## 무엇을 계산하나요?

| 질문 | 계산 기준 |
| --- | --- |
| 게시글별 랜딩 유입 | `landing_viewed` 건수를 `post_id`별로 분류 |
| 샘플 노출률 | 해당 페이지에서 `sample_report_viewed`가 1회 이상 발생한 페이지 방문 수 ÷ `landing_viewed` 페이지 방문 수 |
| 신청 시작률 | `registration_started`가 1회 이상 발생한 페이지 방문 수 ÷ `landing_viewed` 페이지 방문 수 |
| 신청 완료율 | `registration_completed`가 1회 이상 발생한 페이지 방문 수 ÷ `landing_viewed` 페이지 방문 수 |
| 주요 버튼·샘플 사용 | 각 이벤트의 총 발생 횟수와 행동한 페이지 방문 수를 따로 봄 |
| 체류시간·클릭 수 | `page_view_id`별 `visibility_checkpoint`의 누적 최댓값을 먼저 구한 뒤 방문 단위로 비교 |
| 기기·스크롤 | `device_category`와 각 `depth`에 도달한 페이지 방문 수 |

분자와 분모는 같은 기간·같은 방문 단위를 씁니다. 비율은 %로 보려면 100을 곱합니다. PostHog 기본 퍼널은 기본적으로 사용자 기준이므로 페이지 방문 기준과 자동으로 같지 않습니다. 페이지별 전환은 같은 `page_view_id`를 기준으로 집계해야 하며 구현과 쿼리 검증이 필요합니다. 순서가 필요한 퍼널에는 발생 순서도 확인합니다. 샘플 노출은 2초 기준이라 빠르게 신청한 방문자는 누락될 수 있어 필수 단계로 강제하지 않습니다.

한 사람이 같은 버튼을 세 번 누르면 이벤트 3건, 해당 페이지 방문 1건입니다. 한 사람이 새로고침하거나 다른 기기로 접속하면 여러 방문으로 잡힙니다. 현재 로컬 테스트는 `persistence: memory`라 새로고침 후 같은 사람을 안정적으로 구분하지 못합니다. **방문 수와 고유한 실제 사람 수는 다릅니다.**

`elapsed_ms`는 페이지가 열린 경과 시간, `visible_ms`는 브라우저가 해당 탭을 표시 중이라고 보고한 누적 시간입니다. 창을 열고 자리를 비운 시간도 포함될 수 있고 실제 독서를 뜻하지 않습니다. 브라우저 종료·통신 차단·절전 등으로 기록이 늦거나 빠질 수 있습니다. 스크롤도 내용을 읽었다는 증거가 아닙니다. 15초마다 기록되는 중간 이벤트는 PostHog 세션 판단에도 영향을 줄 수 있습니다.

## 유입 링크와 범위

게시글마다 랜딩 URL에 `utm_content=post_001`처럼 팀이 정한 게시글 ID를 붙입니다. `utm_source`는 채널, `utm_medium`은 게시 방식, `utm_campaign`은 실험·후킹 묶음으로 씁니다. 게시글마다 후킹 문구와 ID의 대응표를 팀이 관리해야 합니다. PostHog는 랜딩에 도착한 방문만 기록합니다. **커뮤니티의 게시글 조회 수, 랜딩 이전 링크 클릭 수, 게시글 대비 유입률은 PostHog만으로 확인할 수 없습니다.**

로컬 PostHog 테스트는 실제 URL 값을 그대로 보내지 않고 `post_001`과 `post_002`만 가상의 `test_post_001`, `test_post_002`로, 나머지는 `test_unknown`으로 바꿉니다. 채널·캠페인도 고정 테스트 값입니다. 실제 실험용 유입값 전송은 아직 미구현입니다. 개인정보를 URL이나 이벤트에 넣지 않습니다.

## 변경과 출시 전 점검

- 이전 시안의 `example_exposed`, `example_selected`, `purchase_offer_viewed`, `purchase_clicked`, `availability_notice_viewed`는 **현재 원본 화면에서 발생하지 않습니다.** 과거 테스트 기록과 섞지 않습니다.
- 구매 버튼이 나중에 추가된다면 결제 완료가 아닌 클릭으로 별도 기록하고 실제 서비스·결제 미준비 안내를 연결합니다.
- 신청자 명단은 Google 시트에 별도 보관하는 방향입니다. 이메일·폼 응답은 PostHog로 보내지 않습니다. 가상 신청의 시트 저장·성공 화면과 PostHog 완료 이벤트 도착을 로컬에서 확인했습니다. 운영 환경은 아직 확인하지 않았습니다.
- 실험 전 운영 수집 코드, 허용된 게시글 ID, 동의·고지, 보관·삭제, IP·국외 처리, 팀 권한, 테스트 데이터 분리와 실제 기기 측정을 확인합니다. 코드가 있다고 실제 운영 데이터가 자동 수집되는 것은 아닙니다.
- 측정 대상을 이동하거나 크기를 바꾸면 뷰어 상단 `#viewer .vw-bar`의 50%·2초 조건 및 스크롤 범위를 모바일·데스크톱에서 재검증합니다. 기준이 달라지면 `sample_version`을 올리고 변경 사실을 기록합니다.

대시보드 구성과 내보내기는 [PostHog 대시보드 안내](posthog-dashboard.md), 변경 절차는 [측정 변경 안내](measurement-change-guide.md)를 참고하세요.
