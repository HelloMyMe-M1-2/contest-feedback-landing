# 이벤트 명세

화면이나 PostHog 요구사항을 변경할 때의 검토 결과와 변경 절차는 [측정 변경 안내](measurement-change-guide.md)를 참고하세요. 이 문서는 현재 로컬 이벤트 정의의 기준입니다.

## 지금 어디까지 동작하나요?

실제 실험 수집은 **연결되지 않았습니다.** 일반 화면의 이벤트 전송은 꺼져 있습니다. 로컬 개발 서버에서 `analytics_lab=1`을 붙여 열면 이벤트를 브라우저 메모리에 기록해 살펴볼 수 있고, 새로고침하면 사라집니다. 실습장의 수치는 최대 100건이며 실제 방문자·세션 통계가 아닙니다. 별도의 토큰·호스트와 `posthog_test=1`이 있는 로컬 테스트에서 가상의 유입 정보와 방문·예시 노출·선택·구매 클릭 이벤트가 PostHog 프로젝트에 도착한 것을 확인했습니다.

초기 테스트 이벤트 상세 화면에서 PostHog가 IP와 위치 추정 정보를 저장한 것을 확인했습니다. 이후 프로젝트에서 원본 IP 저장을 끄고 로컬 테스트 이벤트의 GeoIP 비활성화를 요청했습니다. 새 테스트 한 건에서는 IP·위치 항목이 보이지 않았지만 기존 이벤트는 그대로 남습니다. PostHog가 IP를 수신·처리하는 것까지 막는 설정은 아니며, 실제 참가자 수집 전 모든 수집 경로와 고지·동의·보관·삭제 조건을 검토해야 합니다.

실습장에는 페이지를 연 뒤 경과한 시간과 화면이 표시된 시간도 초 단위로 표시합니다. 탭이 숨겨져 있는 시간은 후자에 더하지 않습니다. 로컬에서는 15초마다 누적 시간과 클릭 수를 이벤트로 기록하고, PostHog 테스트 모드를 별도로 켜면 테스트 이벤트를 전송합니다. 새로고침하면 새 페이지 방문입니다.

| 이름 | 의미 | 현재 로컬 실습 |
| --- | --- | --- |
| `landing_viewed` | 페이지 방문 | 기록됨. Strict Mode의 개발용 재실행은 한 번으로 처리 |
| `example_exposed` | 예시 내용 노출 | 요소의 50% 이상이 화면에 보이고 탭이 표시 상태로 2초 유지되면 기록. 각 예시는 페이지 수명 중 1회 |
| `example_selected` | 사용자가 예시 버튼 선택 | 누를 때마다 기록 |
| `purchase_offer_viewed` | 구매 조건 영역 노출 | 50% 이상·2초 유지 시 페이지 수명 중 1회. 가격은 미정 |
| `purchase_clicked` | 구매 버튼 클릭 | 누를 때마다 기록. 결제 아님 |
| `availability_notice_viewed` | 준비 중 안내가 화면에 표시됨 | 표시 후 기록. 이미 열린 안내를 반복 클릭해도 새 표시로 세지 않음 |
| `registration_started` / `registration_completed` | 등록 시작 / 저장 성공 | 형식만 정의. 이메일 수집 보류 |
| `scroll_depth_reached` | 화면의 아래쪽이 25·50·75·100% 구간에 도달 | 각 구간은 페이지 방문당 1회. 처음부터 화면에 보인 구간도 도달로 기록 |
| `visibility_checkpoint` | 누적 표시·경과 시간과 클릭 수 | 표시 중 15초 간격, 탭 숨김과 `pagehide` 시 기록. `visible_ms`, `elapsed_ms`, `click_count`는 누적값 |

이벤트에는 이름, 행동 속성, 유입 정보, 페이지 방문 ID, 기기 구분, 시각과 스키마 버전이 들어갑니다. 이번 변경부터 버전은 `2`이며 기존 `1` 테스트 기록에는 새 속성이 없습니다. `utm_content`는 게시글 ID로 사용합니다. PostHog 테스트에서는 `post_001`, `post_002`만 정해진 가상 식별자로 바꾸고 그 밖의 값은 `test_unknown`으로 처리합니다. 나머지 유입 속성도 고정된 테스트 값입니다. 형식 검사만으로 개인정보를 완전히 차단할 수 없으므로 운영 연결 전 팀이 발급한 값만 허용하는 방식을 정해야 합니다. 임의의 이메일·원고·개인정보는 URL에 넣지 않습니다.

페이지 방문 ID는 페이지를 열 때 새로 발급하는 임의 값으로, 동일 페이지에서 일어난 이벤트를 묶습니다. 사람이나 PostHog 세션과 같은 값이 아닙니다. 기기는 브라우저 정보를 이용한 대략적 분류이며 `mobile`, `desktop`, `other`, `unknown` 중 하나입니다. 태블릿 등이 잘못 분류될 수 있고 원본 브라우저 문자열은 이벤트 속성에 넣지 않습니다.

스크롤은 `data-analytics-content`로 감싼 콘텐츠의 맨 아래를 기준으로 화면 하단이 지나간 비율입니다. 실습장은 이 영역 밖에 있습니다. 새 섹션이 영역 밖에 들어가거나 최종 디자인에서 구조가 달라지면 결과가 틀릴 수 있어 검증해야 합니다. 짧은 페이지는 처음 열 때 여러 구간을 동시에 넘을 수 있습니다. 이후 높이나 화면 크기가 바뀌어도 한 번 기록한 구간은 취소하지 않습니다. 실제 읽기를 뜻하지 않습니다.

전체 클릭 수는 실제 사용자의 페이지 클릭만 합산하며 실습장 조작은 제외합니다. 어떤 요소나 텍스트를 눌렀는지는 이 숫자에 포함하지 않고, 예시 선택과 구매 클릭만 별도 행동 이벤트로 보냅니다. 키보드로 실행되는 클릭도 포함될 수 있고, 스크롤·텍스트 입력은 클릭으로 세지 않습니다.

시간 이벤트는 페이지 방문 ID별 `visible_ms`와 `elapsed_ms`의 **최댓값**을 사용합니다. 같은 누적값을 더하면 안 됩니다. 숨김과 페이지 이탈 시 연달아 기록될 수 있으며 마지막 전송이 누락될 수도 있습니다. `sendBeacon`을 시도하지만 도착을 보장하지 않습니다. 페이지 수명 중 확인된 값으로, 브라우저 절전 등으로 오차가 생길 수 있습니다. 계속되는 중간 기록은 PostHog가 세션을 활동 중으로 판단하게 할 수 있으므로 페이지 시간과 세션 시간을 동일하게 보지 않습니다.

## 앞으로 실제 연결할 때

- 이벤트 횟수와 행동한 페이지 방문 수를 분리한다. 같은 사람이 여러 기기에서 방문한 경우 동일인으로 확정할 수 없다.
- 로컬 노출 감지는 페이지 수명 기준이다. 실제 실험의 세션 기준, 화면 크기, 재노출, 탭 전환, 느린 브라우저와 누락을 별도로 검증한다.
- 구매 조건 노출 후 같은 페이지 방문에서 클릭한 비율과 전체 방문 대비 구매 클릭 비율을 별도로 보고, 가격과 제공 범위 버전을 함께 둔다. 빠르게 클릭해 노출 2초 기준을 충족하지 못한 경우도 전체 클릭 지표에 포함한다. 실제 결제와 구분한다.
- 화면이 표시된 시간은 탭을 연 전체 시간과 구분한다. 강제 종료·통신 실패 등으로 누락될 수 있고 실제 읽기를 증명하지 못한다.
- 이메일 수집을 시작하게 될 경우 저장 성공 응답을 받은 때만 완료로 기록하고 저장소와 분석 수치를 대조한다.
- 운영 데이터를 연결하기 전 SDK의 자동 수집, 식별자, IP·URL, 세션 녹화, 쿠키, 동의, 보관·삭제, 국외 처리와 테스트 데이터 분리를 검토한다. 이메일·원고·입력값을 보내지 않는다.
- 실제 퍼널 측정 전 운영 환경 구분값, 승인된 게시글 ID 목록, 이벤트 전송 중복·오류 처리와 페이지 방문 ID 기준 집계를 구현·검증해야 한다. PostHog 기본 퍼널의 사용자 기준과 페이지 방문 기준을 동일시하지 않는다.
