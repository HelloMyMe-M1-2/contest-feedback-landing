# 화면이나 측정 도구가 바뀔 때

측정의 기준은 화면의 색·문구가 아니라 **사용자가 한 행동과 기록 조건**입니다. 현재 기준은 [이벤트 명세](events.md), 실제 수집 전 남은 일은 [실험 준비 현황](experiment-readiness.md)을 봅니다. 실제 참가자 PostHog 수집은 아직 구현되지 않았습니다.

## 변경 전 확인

| 변경 | 함께 확인할 것 |
| --- | --- |
| 문구·색상 | 행동의 의미와 이벤트 연결이 유지되는지. 실험에 영향을 줄 내용 변화는 기록 |
| 버튼 위치·구조 | 같은 행동이 같은 이벤트로 전달되는지. 주요 버튼에는 고정된 위치 ID 사용 |
| 샘플 뷰어 | 노출 대상·50%·2초 조건과 모바일 노출 가능성 |
| 섹션 추가·이동 | 스크롤 측정 범위인 `data-analytics-content`에 포함되는지 |
| 이벤트·속성 추가 | 명세와 타입, 테스트 전송 허용 목록·대시보드 기준 함께 수정 |
| PostHog SDK·설정 | 자동 수집·URL·IP·식별자와 실제 네트워크 및 수신 결과 재확인 |

이름만 같다고 두 버전의 실험 조건과 결과가 자동으로 같아지는 것은 아닙니다. 행동 의미나 발생 조건이 달라지면 이벤트나 버전을 구분하고 과거 데이터에 무작정 합치지 않습니다.

## 수정 후 검증

1. [이벤트 명세](events.md)에 발생 시점·속성·중복 기준을 기록합니다.
2. 화면과 `src/analytics/`의 연결을 확인하고 `npm test`, `npm run build`를 실행합니다.
3. 개발 실습장에서 관련 행동을 직접 확인합니다. 필요한 경우 가상 데이터로 PostHog 수신 여부와 허용한 속성을 확인합니다.
4. 모바일·데스크톱에서 노출·스크롤·버튼을 확인합니다. 테스트 이벤트를 실제 실험 결과에 섞지 않습니다.

이메일·폼 입력·기획안·비밀값은 이벤트에 넣지 않습니다. 이벤트 송신이 막혀도 신청이나 화면 동작은 계속되어야 합니다. 이벤트 전송 성공, 중복 없는 실제 인원, 실제 읽기 여부를 보장할 수는 없습니다.

운영 연결 시에는 로컬 테스트의 타입 검사와 문자열 형식 검사만으로 개인정보 유입이 차단된다고 가정하지 않고 허용값·수집 설정·고지와 필요한 동의를 별도로 검증합니다.
